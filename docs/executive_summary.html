LazyGraphRAG vs GraphRAG Zero — Evaluation Summary

Date: April 27-28, 2026
Evaluation Framework: BenchmarkQED (V5 pipeline)
Corpus: Leukemia Drug Discovery — 3,071 curated scientific papers, 339K text units

1. What We Did

Objective

Compare LazyGraphRAG (LGR) and GraphRAG Zero (GRZ) search quality on a curated leukemia drug discovery corpus using BenchmarkQED's automated evaluation framework. We tested LGR once and GRZ with 4 different retrieval configurations to find the optimal settings.

Evaluation Pipeline

  1. Corpus Curation: Started with 6,304 papers → keyword + LLM topic scoring → retained 3,071 leukemia-relevant papers
  2. Text Chunking: 339,308 text units (200 tokens each, 40-token overlap) exported from LGR's SQL database
  3. Question Generation (AutoQ): Embedded all chunks → KMeans clustering (k=50) → GPT-5.2 generated 100 questions (50 local + 50 global) with 557 source-grounded assertions
  4. Search: Sent identical 100 questions to LGR and each GRZ configuration
  5. Answer Scoring (AutoE): GPT-5.2 judged each of 557 assertions against each answer (4 trials, majority vote)
  6. Retrieval Metrics: Measured precision, recall, fidelity for LGR (not comparable for GRZ due to chunk boundary differences)

4. Key Findings

LGR wins overall (75.4%), primarily due to a 10+ point advantage on global synthesis questions. Its graph-based retrieval provides broader thematic coverage.
GRZ wins on local questions (83-86%) across all configurations. Its community-based chunk selection excels at finding specific passages for fact-finding queries.
  • Reasoning matters for global: GRZ V1 (with LLM chunk grading) was 4% better on global than V2-V4 (without). Removing reasoning consistently hurt cross-document synthesis.
  • Augmentation backfired: V4 added more diverse sources (13 vs 9 DOIs) but global pass rate dropped 3% — broader context diluted answer quality rather than improving it.
  • Paper settings (V3) = no improvement over simple dropoff (V2): Dynamic elbow detection, LDA query classification, and per-type δ/λ tuning added complexity without measurable benefit.
  • GRZ is 2-4× faster than LGR (~36-70s vs ~80s per question) and up to 8× cheaper ($0.05 vs ~$0.38/query for V2/V3 vs V1).

5. How Assertions Work (Evaluation Methodology)

Assertions are source-grounded unit tests for answer quality:

  1. Claim Extraction: GPT-5.2 reads actual text chunks from the cluster and extracts factual claims (grounded in corpus text, not LLM knowledge)
  2. Assertion Generation: Claims are converted to testable YES/NO statements (e.g., "The response should mention flow cytometry as a method for measuring apoptosis")
  3. Scoring: Each assertion is evaluated against the answer with 4 independent trials; passes if ≥3/4 agree

This ensures we're testing whether the search system retrieved and synthesized information that actually exists in the corpus, not whether the LLM hallucinated a plausible answer.

9. Recommendations

  1. For overall quality: Use LGR — 75.4% pass rate, strongest on global synthesis
  2. For local/fact-finding workloads: GRZ V2 (dropoff) — 85.7% local at $0.05/query
  3. For best GRZ overall: GRZ V1 (reasoning) — 74.6% at $0.38/query
  4. For cost-optimized GRZ: GRZ V2 (dropoff) — 73.4% at $0.05/query (7.6× cheaper than V1)
  5. Avoid: Query augmentation (V4) — adds cost without improving quality
  6. Next steps: Align GRZ chunking with LGR to enable retrieval recall comparison; test with larger embedding model
