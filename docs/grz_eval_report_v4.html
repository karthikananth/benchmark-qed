How Query Augmentation Works

For each question, the augmentation pipeline:

  1. Generates 10 follow-on queries using gpt-5.2 — sub-questions exploring different aspects of the original query
  2. Retrieves 50 chunks per follow-on query from the nearest-neighbor index
  3. Unions all retrieved chunks with the original query's chunks, deduplicating
  4. Applies the 200-chunk budget to the merged pool via dropoff sampling
  5. Generates the final answer from the augmented context

6. Analysis: Why Augmentation Didn't Help

The Paradox: More Sources, Worse Scores

V4's augmentation successfully broadened source diversity (13 DOIs vs 9 for global queries in test), yet assertion pass rates decreased. Several factors may explain this:

  • Context dilution: The 200-chunk budget is fixed. Augmentation brings in chunks from 10 follow-on queries, but these compete with the original query's most relevant chunks for the same 200 slots. The result: broader but shallower coverage per topic.
  • Follow-on query quality: The 10 generated follow-on queries may explore tangential aspects rather than the core themes the assertions test. The assertions are grounded in the cluster's central topics — if augmentation pulls in peripheral material, it dilutes rather than enriches.
  • Union deduplication effects: Unioning chunks from multiple queries may inadvertently prioritize chunks that appear in multiple follow-on retrievals (popular but generic text) over rare but highly relevant passages.
  • Answer generation pressure: With a broader but less focused context window, gpt-5.2 may produce more "survey-like" answers that mention many topics superficially rather than covering the assertion-tested themes in sufficient depth.

Local Questions: Unaffected (85.3%)

Local question performance remained identical to V3, confirming that the LDA query classification correctly identifies local queries and applies minimal augmentation to them.

Comparison with V1 (Reasoning)

V1's reasoning approach (LLM-graded chunks) remains the best GRZ configuration for global questions (65.5%), despite being the most expensive (~$0.38/query). The key difference: reasoning evaluates each chunk's relevance to the specific question, while augmentation generates related but different questions. Relevance filtering is more valuable than query expansion for assertion-based evaluation.

8. Summary

GraphRAG Zero V4 (v9 with query augmentation) tested whether LLM-generated follow-on queries could close the global question gap with LGR. The results are clear:

  • Augmentation did not improve global questions — pass rate dropped from 61.2% (V3) to 58.3%, widening the gap with LGR to 13.1 points
  • Local questions remain strong at 85.3%, confirming LDA classification correctly shields local queries from augmentation effects
  • More sources ≠ better answers — the test query showed 13 DOIs vs 9, but broader context diluted answer quality rather than improving it
  • V1 (reasoning) remains the best GRZ overall — LLM-based relevance filtering outperforms LLM-based query expansion for this evaluation

Recommendations:

  1. For maximum GRZ quality: use V1 (reasoning) settings — accepts higher cost (~$0.38/query) for best global coverage
  2. For cost-optimized deployment: use V2 (dropoff) — $0.05/query with strong local (85.7%) and acceptable global (61.2%)
  3. For augmentation to work: likely needs higher-quality follow-on query generation, stricter relevance filtering of augmented chunks, or a larger chunk budget (>200)
  4. To match LGR on global: the fundamental gap appears architectural — GRZ's community-based retrieval lacks LGR's graph-traversal diversity advantage
