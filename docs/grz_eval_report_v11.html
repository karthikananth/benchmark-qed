3. Evaluation Pipeline

The evaluation uses the BenchmarkQED framework with a V5 pipeline design. Questions and assertions were generated from the corpus text using AutoQ, then the same 100 questions were sent to GRZ for answering.

Pipeline Stages

Stage 1: AutoQ (Question Generation)
  └─ Embed (339K chunks) → Cluster (k=50) → Generate questions + assertions
  └─ Output: 100 questions (50 local + 50 global), 557 assertions

Stage 2: GRZ Search
  └─ Send 100 questions → GRZ REST API (POST/GET polling)
  └─ Output: 100 answers

Stage 3: AutoE (Assertion Scoring)
  └─ Score each answer against source-grounded assertions using GPT-5.2
  └─ Output: pass/fail per assertion, coverage metrics

LLM Configuration (Evaluation)

All evaluation LLM calls (question generation, assertion generation, assertion scoring) used GPT-5.2 with temperature: 0.0, reasoning_effort: none, and seed: 42 for deterministic, reproducible results.

Interpretation

  • Local (87.7%): GRZ excels at document-specific fact-finding. The DiskANN vector search with dropoff sampling effectively identifies the most relevant passages for targeted questions.
  • Global (61.5%): Cross-document synthesis is more challenging. The community-based retrieval covers approximately 61% of the thematic assertions, indicating some relevant topical clusters are not represented in the retrieved chunks.

Key Observations

  • Overall: Near-parity — GRZ is within 0.8% of LGR on average pass rate, with a minimal and simple configuration
  • Local advantage (GRZ +8.4%): GRZ's DiskANN vector search with community-based chunk grouping is highly effective for targeted fact retrieval, outperforming LGR's graph-based approach by a significant margin
  • Global advantage (LGR +9.9%): LGR's graph-based retrieval with lazy evaluation provides broader thematic coverage for synthesis questions that require spanning multiple topics across the corpus
  • Architectural trade-off: The systems have complementary strengths — GRZ prioritizes retrieval depth (finding the best chunks for a specific topic), while LGR prioritizes retrieval breadth (covering diverse topics)

9. Summary

GraphRAG Zero with the v11 configuration — the simplest possible setup (pure vector search → dropoff sampling → single LLM call) — delivers competitive results:

  • 74.6% overall assertion pass rate, within 0.8% of LazyGraphRAG (75.4%)
  • 87.7% on local questions — the highest local score observed, surpassing LGR by 8.4 points
  • 61.5% on global questions — 9.9 points behind LGR, reflecting the inherent limitation of embedding-based retrieval for cross-document synthesis
  • ~31 seconds per question — fast and cost-efficient with a single LLM call per query

Conclusion: GRZ v11 demonstrates that a minimal, well-tuned vector search configuration can match LGR overall while excelling on local fact-finding queries. The global question gap represents an architectural difference — graph-based retrieval provides natural thematic diversity that pure vector search cannot replicate without additional mechanisms.
